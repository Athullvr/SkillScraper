# Limitations

- The relevance weights and `0.34` threshold are initial hypotheses. A 20-task exploratory set and a separate 15-task evaluation v1 set are documented, but live candidate outcomes and ordinary-search comparisons remain unmeasured because authorized catalog access was unavailable. Both sets are small and do not support general claims.
- Search results come from skills.sh; authentication, rate limits, unavailable results, and catalog changes can affect discovery. SkillScraper does not crawl the full catalog.
- Only up to five candidates can be configured for detail inspection; the default is three. A relevant result outside that inspected set may be missed.
- Project context reads only direct-root allowlisted metadata. It cannot verify compatibility from source code, scripts, runtime environments, or transitive dependency behavior.
- Local security checks are heuristic. Obfuscated, indirect, or novel malicious behavior may be missed, and legitimate content may trigger warnings.
- `USE` requires a passing revision-bound audit younger than 90 days. Many skills have no audit, no content hash, or audit results without revision association; those cases remain `REVIEW`.
- The optional LLM can add task-fit perspective, but its language and score are model judgments. Deterministic policy and local/external security evidence remain authoritative.
- The install command is generated text only. SkillScraper does not install, activate, cache, or execute a candidate.
- MCP is a local stdio adapter over the same recommendation and inspection workflows. Registration does not guarantee host invocation. In an observed Codex CLI run, a routine README typo prompt did not call SkillScraper unless explicitly asked; add a host instruction or prompt when consistent pre-selection assessment is required. This single routine-task observation does not establish behavior for every host or task.
- MCP calls do not use the optional LLM adapter. Catalog-backed task search still transmits the heuristically redacted task query to skills.sh (or the configured compatible catalog); project source files are not transmitted. Catalog credentials are used for catalog authentication and are not exposed in tool results.
- MCP results intentionally omit the absolute project path and bound evidence lists for compactness. Truncation counts are included where audit, local finding, or inspected file lists are capped.
- MCP evidence packets return up to three task-term-matched excerpts from files already inspected in the current request. The default budget is 1200 UTF-8 bytes of excerpt bodies, the hard maximum is 2400 bytes, and each excerpt is capped at 600 bytes. `used_bytes` excludes response metadata. Selection is lexical and deterministic; it can miss useful guidance that uses different wording, and a passage may be clipped. Packets do not include line numbers, and scanner warnings apply to the file rather than a precise range.
- Hashes identify the detail response represented by the catalog; they do not authenticate its publisher. If the detail hash is missing, returned excerpts are explicitly unbound. No excerpts are returned when the in-memory detail identity or hash differs from the policy evidence.
- Evidence gap next steps describe what could address a specific uncertainty. They cannot produce an audit, make a partial detail complete, or turn a heuristic scan into proof of safety.
- The skills.sh API reference documents bearer authentication for API requests and explicitly marks the audit endpoint as authentication-required. It documents Vercel OIDC as the credential path, but no unauthenticated search/detail route or separate API key is documented. SkillScraper does not read `.env.local` or refresh OIDC tokens. No alternate catalog source has been tested; any configured endpoint must match the existing skills.sh v1 paths and response models.
- The MCP stdio path rejects symlink components in the selected project path and the project scanner skips symlinked metadata files. Filesystem race conditions are not eliminated by this application-level path validation.
