# Troubleshooting

Use `skillscraper` for new CLI invocations. The `skillscout` command, `skillscout-mcp` and `skillscout-codex-hook` executables, `skillscout` Python import path, and `SKILLSCOUT_*` environment variables remain supported for compatibility.

## First-run checks

- Check the installed entry point and local settings with `skillscraper --version` and `skillscraper doctor`. Doctor reports whether credentials are configured, but never tests catalog connectivity or prints their values.
- Confirm the local fast path with `skillscraper recommend "Rename a local variable in a helper function." --format json`. The expected decision is `NO_SKILL_NEEDED`; this task does not load catalog settings or make a network request.
- `skillscout-mcp` is the retained stdio server command. It waits for an MCP client and intentionally emits no startup banner on stdout. Run it from a terminal only as a short startup check, then stop it with Ctrl+C. For a handshake and tool-call check against an installed wheel, follow the `mcp_stdio_smoke.py` command in the README.
- SkillScraper provides example configuration for Claude Code and Codex CLI in the README. Copy the example into the client configuration you choose and set `command` to the installed `skillscout-mcp` path if it is not on the host's `PATH`. SkillScraper does not create or edit client configuration files.

- **`skillscraper`, `skillscout`, or `skillscout-mcp` is not found**: activate the virtual environment where you installed the wheel, or add that environment's `bin` directory (`Scripts` on Windows) to the MCP host's `PATH`. From a development checkout, run `uv sync` and use `uv run skillscraper`.
- **The MCP host cannot start SkillScraper**: run `skillscraper doctor`, confirm the configured command is available to the host process, and check the host's MCP process logs (diagnostics go to stderr). If using a virtual environment, point `command` to its installed `skillscout-mcp` console script.
- **Codex does not add a SkillScraper result before the prompt**: confirm the installed `skillscout-codex-hook` absolute path in `~/.codex/hooks.json` or the project `.codex/hooks.json`, then open `/hooks` in Codex to review and trust the current hook definition. `UserPromptSubmit` runs on every prompt and does not support a matcher. A fixture check is available through `scripts/mcp_stdio_smoke.py`; it does not replace a Codex client session test.
- **The Codex hook returns `REVIEW`**: an invalid hook event or a configuration, credential, network, timeout, incomplete-search, or catalog-response failure does not become `NO_SKILL_NEEDED`. Run `skillscraper doctor`; for catalog failures, verify that authorized credentials are available to the Codex process and that it can reach the configured HTTPS endpoint. The hook suppresses upstream error text and credential values. It returns no catalog text or candidate instructions to the model.
- **The Codex hook slows prompt submission**: it runs synchronously before each prompt. Routine local tasks do not read catalog configuration; other prompts may make a catalog-backed check. Remove the `UserPromptSubmit` entry from the client config to disable it, or use only the MCP server and explicit `prepare_task` calls.
- **An entry point reports missing dependencies**: install or upgrade the wheel without `--no-deps` in the same environment as the entry point, then verify with `python -m pip check`.
- **The Codex hook reports missing dependencies**: reinstall or upgrade the SkillScraper wheel without `--no-deps` in the environment named by the hook's `command`. It returns a JSON `REVIEW` context and does not make a no-skill decision.
- **Python version error**: install Python 3.12+ and ensure uv selects that interpreter.
- **Invalid configuration**: `doctor` and tool errors identify the setting and expected format. Correct that environment variable and restart the MCP server; credential values are not printed.
- **Catalog credentials**: configure `SKILLSCOUT_CATALOG_TOKEN` or `VERCEL_OIDC_TOKEN` in the environment of the MCP host process using your OS or team's secret manager. If both are non-empty, `SKILLSCOUT_CATALOG_TOKEN` takes precedence. Do not place the value in shell history, task text, logs, or client configuration. For the documented Vercel flow, enable OIDC Federation and use `vercel link` and `vercel env pull`; securely pass the resulting token to the host process. SkillScraper does not load `.env.local` or refresh OIDC tokens. Restart the MCP server after renewing an expired token.
- **Catalog 401/403**: the error distinguishes missing credentials from a rejected credential or insufficient access. Verify that the token is current and available to the process that launches SkillScraper. The skills.sh API requires bearer authentication, including for audits; local `doctor` and routine `NO_SKILL_NEEDED` decisions do not require it.
- **Catalog 429/503**: SkillScraper respects `Retry-After` and retries a bounded number of times; retry later if the endpoint remains unavailable.
- **Catalog timeout or connection failure**: check the host's network/DNS access and `SKILLSCOUT_REQUEST_TIMEOUT_SECONDS` (1–120 seconds). SkillScraper bounds the request window and retry count. Retry later if the connection problem persists; a failure is returned as an operational error, not as `NO_SKILL_NEEDED`.
- **Catalog HTTP error**: permanent request failures are not retried. Check that the configured HTTPS base URL implements the skills.sh v1 API and that the requested skill ID exists.
- **Incomplete search**: if the result page reaches its limit or indicates another page, a low-relevance result remains `REVIEW`. Retry later or review the available catalog results; SkillScraper does not treat that page as evidence that no skill exists. A completed empty search and an incomplete empty search have different outcomes.
- **`REVIEW` with no audit**: no audit result is known for that skill/revision. This is not a pass; inspect the source and decide manually.
- **`REVIEW` with unknown compatibility**: add project metadata in an allowlisted root file or treat the result as a task-only assessment. SkillScraper does not inspect source trees.
- **`REVIEW` with unresolved evidence**: follow the candidate's `unresolved_evidence` and `next_steps` fields. They distinguish missing, unavailable, stale, mismatched, and incomplete evidence. They describe evidence to obtain or review and do not change the decision automatically.
- **Empty evidence packet**: no inspected paragraph matched both a task term and, optionally, declared project technology under the deterministic lexical selector. The input budget may be zero to disable excerpts; otherwise check the packet's `explanation` and `truncated` fields. The packet is not a full skill document.
- **JSON parsing**: use `--format json`; errors are JSON on stdout with `schema_version` and `error` fields.
